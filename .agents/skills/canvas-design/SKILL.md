# Canvas design — deliberate visual artifacts

When the deliverable *is* an image (not an interface), the design decisions are
the product. Work like a designer: concept first, composition second, polish last.

## Method

1. **Concept.** What is the one idea the viewer takes away? Write it in a
   sentence. Every element either serves it or is cut.
2. **Composition.** Choose a structure before drawing: centered monument,
   asymmetric grid, rule-of-thirds anchor, full-bleed with negative space.
   Establish a focal point and a reading path. Negative space is an element —
   budget it explicitly.
3. **Type (when text is present).** Two type roles maximum beyond the display
   face. Set hierarchy by size/weight/tracking, not by adding fonts. Align type
   to the composition grid.
4. **Color.** A named palette (3–5 roles: ground, primary, accent, tint, ink),
   applied with discipline. Use color to direct attention, not to fill space.
5. **Depth and texture.** Grain, subtle gradients, and shadow can add material
   presence — one restrained pass, not five effects.
6. **Export intent.** Deliver at the right resolution and format (PNG for
   screens, PDF/vector for print), with the aspect ratio the user needs.

## Craft rules

- Render with the project's existing tooling (canvas/HTML/SVG); no design-tool
  detours unless asked.
- Check the piece at thumbnail size — if the composition collapses, it will
  fail everywhere small.
- Title-safe margins for anything with text.
- Deterministic or parameterized output when the artifact is generated by code,
  so the user can regenerate variants.

## Examples

- "Make an album cover, dark and hypnotic" → concept sentence, then a
  full-bleed composition with one dominant form, restrained palette, and grain.
- "Export a conference slide background" → 1920×1080, quiet center for the
  speaker's title, texture only at the edges.
